### F2 — P2 — `og:type` hardcoded to "website" for paper/progress pages

**Severity**: P2 (SEO completeness, social card metadata)

**Description**: `BaseLayout.astro` hardcodes `og:type="website"` for all pages. Open Graph best practice is `og:type="article"` for content pages (paper slides, paper summaries, progress slides, progress reports). The hostname-based or URL-based approach is the cleanest minimal-diff fix (no per-page prop).

**Evidence**:
```

$ grep -oE 'og:type[^>]*' dist/zh/paper/2606.18246/summary/index.html
```

## Known Limitations (documented, not bugs)

1. **`public/_headers` is dead code on GH Pages user/org sites** — per `BaseLayout.astro:55-57` comment, GitHub Pages only serves `_headers` for Project Pages sites, not user/org sites. CSP is injected via `<meta http-equiv>` instead. Documented in `public/_headers.README.md`.

2. **`Astro.response.status = 404` no-op in static build** — `src/pages/[lang]/404.astro:38` sets status 404, but this only works in SSR mode. For static, the page is generated but the server returns 200. GH Pages handles 404 via `public/404.html` fallback (which IS used as the actual 404 response). The 404.astro pages are display aliases only.

3. **`og:image` is generic home image, not per-product** — All 12 product pages use `og-home-{lang}.png` as the OG image. Per-product OG images would be a larger feature (mmx gen + 24 images), not in scope for this sweeper.
